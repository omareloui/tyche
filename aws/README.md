# AWS deployment

One `t4g.micro` ECS host (ECS-optimized AL2023, arm64) in `eu-central-1a` (Frankfurt), no load balancer:

- **Task** `tyche-task` (`networkMode: host`): `tyche-container` on `:3333` + `caddy` on `:80`/`:443` (a Caddyfile written on start: proxies `$DOMAIN`, redirects the former domains of `$REDIRECT_FROM` (`up.sh`, default `tyche.omareloui.com`) to it keeping the path; Let's Encrypt certs).
- **Data** on a separate encrypted gp3 volume `tyche-data`, mounted at `/srv/tyche` (`data/` → `/app/data`, `logs/` → `/app/logs`, `caddy/` → Caddy's certs). It outlives the instance (`DeleteOnTermination=false`).
- **Secrets** in SSM Parameter Store: `/tyche/JWT_SECRET`, `/tyche/GOOGLE_CLIENT_ID`, `/tyche/GOOGLE_CLIENT_SECRET` (SecureString), `/tyche/ADMIN_TENANT_IDS`, `/tyche/VAPID_PUBLIC_KEY` + `/tyche/VAPID_PRIVATE_KEY` (Web Push of the app badge, generated by `up.sh` with `go run ./cmd/vapid`; changing them drops every installed app's subscription).
- **Backups**: a DLM policy snapshots every volume tagged `Backup=tyche` daily at 03:00 UTC (keeps 14) and copies them to `eu-west-1` (kept 7 days). The tenant DBs and `shared.sqlite` (the vault keys of the encrypted tenants) share the volume, so they're always snapshotted together.
- **Access**: no SSH, use SSM (`aws ssm start-session --target <instance id>`).
- **Deploys**: pushing to `main` runs `.github/workflows/deploy.yml` (arm64 runner → ECR → new `tyche-task` revision). The service runs a single task (`minimumHealthyPercent=0`): the old task stops before the new one starts, a few seconds of downtime.

## Setup

```bash
ADMIN_TENANT_IDS=GL_123 aws/infra/up.sh [image]
```

`up.sh` creates what's missing (default VPC, security group, IAM roles, SSM params, data volume, instance, Elastic IP, ECR lifecycle, log retention, snapshot policy, task definition, service) and prints the public IP. It can be re-run. Then:

1. Point the A records of `tychefortune.com` and the `REDIRECT_FROM` domains (`tyche.omareloui.com`) to the Elastic IP (a registrar's URL redirect has no certificate, so https links of the old domain would time out).
2. Add `https://tychefortune.com/oauth/cb` (and the mobile callback) to the Google OAuth client's redirect URIs.

## Restore a snapshot

```bash
aws ecs update-service --cluster tyche --service tyche-service --desired-count 0
aws ec2 create-volume --snapshot-id <snap> --availability-zone eu-central-1a --volume-type gp3 \
  --tag-specifications 'ResourceType=volume,Tags=[{Key=Name,Value=tyche-data-restored},{Key=Backup,Value=tyche}]'
aws ec2 detach-volume --volume-id <old volume>
aws ec2 attach-volume --volume-id <new volume> --instance-id <instance> --device /dev/sdf
aws ec2 reboot-instances --instance-ids <instance>  # remounts by label
aws ecs update-service --cluster tyche --service tyche-service --desired-count 1
```

Then tag the new volume `Name=tyche-data` (and the old one something else) so `up.sh` finds it. A snapshot of another region is copied back first (`aws ec2 copy-snapshot --source-region eu-west-1 ...`).

## Move region

Same domain and secrets, so sessions, vaults, OAuth and the phones keep working (Caddy's certs are on the volume).

1. Copy the image to the new region's ECR (`docker pull --platform linux/arm64`, tag, push).
2. Scale the old service to 0, snapshot `tyche-data`, `aws ec2 copy-snapshot --source-region <old> --region <new> --encrypted`, create a volume from it in the new AZ tagged `Name=tyche-data`, `Backup=tyche`.
3. `AWS_REGION=<new> AZ=<new az> FROM_REGION=<old> aws/infra/up.sh <image>` (copies the SSM params).
4. Set the `Production` environment vars `AWS_REGION` and `ECS_CLUSTER`, point the A record to the new Elastic IP.
5. Once it works, delete everything of the old region (service, cluster, task definitions, instance, volumes, EIP, security group, ECR repo, SSM params, log group, DLM policy, snapshots).
